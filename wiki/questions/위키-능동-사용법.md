# 위키 능동적 사용법

위키를 능동적으로 쓰는 핵심은 **"입력 → 트리거 → 회수"** 세 박자를 습관화하는 것이다. 도구가 아니라 **루틴**이 위키를 살린다.

## 1. 입력 — `.raw/`에 던지기만

자료를 받으면 본인이 1초 자문한다: **"이거 어느 모드?"** → 해당 폴더에 그대로 떨군다. 가공 X, 이름 정리 X.

> **순서 주의**: 본인이 먼저 `.raw/<모드>/`에 파일을 떨군다 → 그 다음 Claude에게 "ingest [파일명]" 트리거. Claude는 떨군 다음 단계에서만 개입한다.

| 받은 것 | 떨굴 곳 |
|---|---|
| 논문 PDF, 블로그 클립 | `.raw/E-research/` |
| 본인 코드 dump, README | `.raw/B-github/` |
| 회사 JD, 회의록 | `.raw/C-business/` |
| 책/강의 노트 | `.raw/F-books/` |
| 일기, AI 대화 로그 | `.raw/D-personal/` |
| 웹페이지 dump | `.raw/A-website/` |

모드 판단이 애매하면 그때만 Claude에게 "이거 어디 넣어야 해?" 물어본다.

## 2. 트리거 — 슬래시 한 줄

| 상황 | 명령 |
|---|---|
| 자료 던졌으니 위키화 | `ingest [파일명]` 또는 `/wiki-ingest` |
| 여러 개 한꺼번에 | "ingest all in .raw/E-research/" |
| 주제 자율 리서치 | `/autoresearch [주제]` |
| 지금 대화를 노트로 | `/save` |
| 위키 안에서 질문 | `query: [질문]` (인덱스 먼저 읽고 답함) |
| 헬스체크 | `/wiki-lint` |
| 시각화 | `/canvas` |

## 3. 회수 — 질문을 위키에 먼저

새 주제는 검색엔진 대신 **위키에 먼저** 물어본다. 예: "OpenPose가 뭐였지?" → Claude가 [[cao-2017-openpose-paf]] 읽고 답한다. 답이 좋으면 `/save`로 [[wiki/questions/]]에 적립 — 이게 위키가 **복리로 쌓이는** 핵심 메커니즘이다.

## 능동성을 만드는 4가지 루틴

1. **주 1~2회 인제스트** — 읽은 자료 한 개라도 `.raw/`에 떨구고 `ingest`. 0이면 위키는 죽는다.
2. **본인 프로젝트 결정마다 ADR** — "왜 이 스택을 골랐는지" `wiki/decisions/`에 쌓기 ([[fullstack-dev]] 도메인).
3. **논문 → 프로젝트 연결** — 새 논문 인제스트 후 "이 개념을 내 프로젝트 X에 어떻게 적용?" 한 줄이라도 [[dev-notes]]에 메모. **크로스 도메인 링크가 가치의 원천**이다.
4. **월 1회 `/wiki-lint`** — 고아 페이지/끊긴 링크 정리. [[hot]]도 갱신.

## 실패 모드

- **떨구기만 하고 트리거 안 함** → `.raw/`만 쌓이고 위키는 멈춤
- **본인 프로젝트 인제스트 안 함** → AI 논문만 쌓이고 [[fullstack-dev]] 영역이 비어 크로스 도메인이 안 됨
- **`/save`를 안 함** → Claude가 한 좋은 답변이 채팅 히스토리에 묻혀 휘발
